# Go as Implementation Language

Status: proposed

Go makes cross-platform binaries and process control easier. Compared to a script runtime, later distribution is easier to try out. Interactive process handling and Windows behavior must be verified before acceptance.

## Evidence so far

The change bw-process-adapter gave the first evidence on process handling, as of 15 November 2026:

- **Non-interactive commands.** `internal/bwcli` starts `bw` with the standard library alone: an environment built from an allowlist, empty standard input, standard output in memory with a limit, standard error read as a stream, a time limit, and on Unix a process group that is killed as a whole. Its tests run against a fake `bw` built from this repository, without a shell or Node. They pass in the dev container on Linux arm64, and the package builds and passes `go vet` for darwin and windows.
- **Interactive login.** In the [manual login exercise](../research/login-exercise-2026-11-15.md) against Vaultwarden 1.37.4, the login started from a Go parent worked on Linux arm64 with the npm `bw` and on macOS arm64 with the official single-file `bw`. No pseudo-terminal was needed. After an interrupt at the password prompt the terminal echoed again on both systems, with the terminal state saved and restored through `golang.org/x/term`. The interrupt reached `bw` without a signal to the Go parent, and the login was reported as failed through the check of the session key form.
- **Cross-compilation.** The tool for the exercise was built for darwin/arm64 in the dev container and ran on the Mac without changes.

## Open before acceptance

- **Windows.** Neither the login nor saving and restoring the terminal state has run on Windows. Stopping `bw` on a timeout kills only the started process there, and with the npm layout, started through a command script, the Node process may keep running. Access control lists for the profile are not set. The procedure of the exercise is written so that it can be repeated on Windows.
- **CI for the process tests.** The tests of `internal/bwcli` and `internal/profile` against the fake are meant to run in CI on Linux amd64, macOS and Windows. The first such run is not recorded yet.
